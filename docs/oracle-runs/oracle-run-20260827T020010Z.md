## ⚠ Notable finding: deterministic-step stamp gap can recur

`chinese/backfill-tones` and `chinese/backfill-numbered-pinyin` (and any other
manifest entry with `deterministic: true`) are vulnerable to this same gap
whenever a row's column was populated by something other than the stamped
pipeline — an import script, a manual backfill, or an earlier pre-stamping
era of this same pipeline. The symptom is specific and diagnosable: the
planner/promoter block on a step, but running that step directly reports
"0 needing backfill." The fix is always `--stale` on that specific script,
never a hand-written stamp or column edit. This is now the **4th
consecutive round** (per `oracle-cron.solo.log`) to hit this exact pattern
on `backfill-tones`/`backfill-numbered-pinyin` — worth a permanent fix
(e.g. a one-time migration that stamps every row whose column is already
non-null) rather than continuing to patch it per-round.
