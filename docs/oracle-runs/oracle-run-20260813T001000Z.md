## 8. Defects found (not fixed — recorded per the skill)

1. **`backfill-tones` / `backfill-numbered-pinyin` report "already have data" while the
   planner lists them pending.** The rows are populated but carry no run-log stamp, so
   the planner sees a missing stamp and the script sees a filled column. Workaround
   used every round: re-run with `--stale`. Recurring; worth a one-time stamping sweep.
2. **gsa mis-segmentation inside generated example sentences.** Observed this run:
   - `请车主尽快挪一下车` → `一` + `下车` (should be `一下` + `车`)
   - `他用车吃掉了我的马` → `他用` + `车`
   - `城门外的车马声…` → `城` + `门外`
   - `画中的车马…` → `画` + `中的`, and `得很` merged
   - round 3: `展厅` split into `展` + `厅` in an 自动车 sentence
   Same class as the earlier 长沙 → 长/沙 defect. The segment labeler is forced to
   label the wrong units, so the stored per-segment metadata inherits the error.
3. **安 lacks tone digits on some proper-noun rows** (seen in round 1) — pinyin present
   without tone marking.
4. **法克 keeps surfacing at the head of `--new` plans** even though it can never ship.
   The `--new` curation filter drops `%`/`110`/`A片`/`surname X` stubs but has no
   vulgar-sense filter.
