## Recurring manifest quirk: unstamped "always" steps (6th consecutive round)

`backfill-tones` and `backfill-numbered-pinyin` are `when: 'always'` manifest steps
gated on `column IS NULL`. Because the columns were already populated (pre-existing
data), each script's early-exit path skipped `stampEntries`, so the planner and
`promote-discoverable.js` both kept reporting the step pending from a missing
`enrichmentLog` stamp alone — `promote-discoverable.js --words=<batch>` (dry-run)
initially showed 19/20 "not ready" until `--stale` was passed to both scripts to
force-stamp the already-correct data. This is now the 6th consecutive round hitting
this exact issue (rounds 527, 528, 530, 531, and now 532) — worth fixing at the
manifest/planner level (e.g. planner could treat "script itself reports 0 pending"
as authoritative) rather than re-discovering it every round.

## Sense-disambiguation gap: 乐's yuè "music" reading (3rd consecutive round)

`backfill-breakdown-senses`'s candidate list for 乐 only ever offers "happy / joyful"
or "to laugh" — never the yuè "music" reading. 乐学者 (musicologist) needed the music
sense and had none available, so it was tagged "happy / joyful" under protest with a
reviewNote, and its breakdown-elaboration sentence had to spend its budget correcting

auspicious-naming sense, so no reviewNote was needed for those. This is the 3rd
