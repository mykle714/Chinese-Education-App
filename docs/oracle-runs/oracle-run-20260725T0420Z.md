## 5. Per-script accounting

| Script | behaviour this run |
|---|---|
| `spanish/mark-discoverable.js` | The only path used to set `discoverable`. One representative row per word; pointer-stub reps auto-skipped. **No bare `UPDATE … SET discoverable = TRUE` was ever issued.** |
| `split-semicolon-definitions` / `expand-abbreviations` | 0 rows changed (source already clean). |
| `parts-of-speech` (author → critic) | Identity regroupings for single-POS words; hand-authored groupings for every multi-POS head-word (§3). Always `--dry-run` first, actions reviewed, then applied. 0 `droppedSenses`, no gender-homograph collapse arose (two-gender words were deliberately excluded — §6). |
| `process-definitions-array` (Pass-1 → critic → short gloss) | The workhorse: re-ranked to put the everyday sense first, pruned vulgar/broken/pointer glosses (§6), and synthesised ≤20-char lead glosses. |
| `long-definitions` (gen → validator) | One 25–125-char, pure-ASCII, non-contrastive, non-self-referential definition per POS **per row**. All accepted on the first validator pass. |
| `example-sentences` (gen → per-sentence validator) | 3 sentences/row with a full per-token `partOfSpeechDict`. **~1,365 sentences authored; 0 flagged by the validator, 0 Opus repairs.** |
| `vernacular-score` | Two 1–5 integers per row, judged on the row's finalised sense set. |

**Sentence construction:** sentences were hand-written, but each `partOfSpeechDict` was
*built from the sentence's own tokens* against a shared tag lexicon, with an untagged
token raising a hard error. Coverage of every whitespace token is therefore guaranteed by
construction, not by inspection — four real gaps (`mucha`, `ante`, `estas`, `difícil`)
were caught this way and fixed rather than silently shipped.

## 7. Defects found

1. **`spanish/backfill-vernacular-score.js` ignores `--words=`.** Its row query
   (`backfill-vernacular-score.js:210-218`) filters only on `language='es' AND discoverable
   AND ("vernacularScore" IS NULL OR "difficulty" IS NULL)` — the `--words` argument is
   parsed nowhere. Every other es script honours it. Consequence during this run: a round
   scoped to batch N also picked up any unscored rows left by a neighbouring batch, which
   halted the round until the answers for those words were supplied too. **Suggested fix:**
   add the same `wordsFilter` clause the sibling scripts build (e.g.
   `backfill-example-sentences.js:67-71`).
2. **Adjective rows can receive the noun row's long definition** (oracle-side bug, but it
   points at a real hazard). The long-definitions prompt is emitted **per row**, naming only
   that row's POS. My first multi-POS batch supplied one definition per *word*, so
   `científico`, `mecánico`, and `obrero` each got a person-shaped definition on their
   adjective row. **Detected and repaired in-run** (§8). Any future generator that keys
   content by head-word instead of by row will hit the same trap.
3. **Damaged source glosses persist in `dictionaryentries_es`.** Three distinct shapes:
   unbalanced parentheses from semicolon splitting (§6), raw Wiktionary markup —
   `cuidar`'s lead gloss is `to look after, take care of (e.g. a house, a person)
   [[[Appendix:Glossary#transitive_verb|transitive]] or +de (of)]` — and etymology
   brackets. Pass-1 may not rephrase, only reorder or drop, so these can only be fixed at
   import time. `cuidar` was skipped for this reason and is a good first test case.
4. **`process-definitions-array` has no per-row `doneGate`,** so it re-reads every
   `--words` row on each apply pass. An index-permutation answer would oscillate forever;
   answers must be idempotent (the settled order re-served verbatim). Not a bug in the
   script, but a sharp edge worth documenting for the next oracle run.

## 11. Uncertain / worth a human look

- **`avanzar` as a transitive "bring forward in time"** ("Tenemos que avanzar la reunión al
  lunes"). The source lists the sense and the RAE allows it, but `adelantar` is far more
  common in everyday speech. Shipped; flagging for a native check.
- **`presupuesto` as an adjective** ("El coste presupuesto cambió al final"). The source has
  the adjective row; the usage is stiff. If a native reviewer disagrees, hide the adj row.
- **`cumbre` as an adjective** ("su obra cumbre") — correct, but appositive rather than a
  normal attributive adjective.
- **Regional spread.** Choices lean Peninsular where the source offered a split
  (`fregona` = mop, `piso` for apartment, `coche` for car, `zumo` for juice, `billete` for
  ticket). Fine for a Spain-first learner audience; worth a decision if Latin American
  Spanish is a target.
- **`cuchara`-style single-sense entries** left with a bare one-word definition are correct
  but thin; the long definition carries the weight on those cards.
- **`backfill-icons` was NOT run** for any word this session — it makes outbound icons8 HTTP
  calls the oracle cannot answer. Every one of the 414 new head-words still needs an icon.
