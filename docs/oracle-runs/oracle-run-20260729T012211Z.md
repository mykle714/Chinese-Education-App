## Findings (not fixed in this run)

1. **`backfill-numbered-pinyin` never stamps `enrichmentLog`.** It reports "0
   entries needing backfill" for an already-populated row and exits without
   writing a stamp, so `oracle-plan.js` re-lists it on every subsequent plan for
   the same word. Cosmetic (the step is deterministic and idempotent), but it
   makes a plan look unfinished forever. Fix: stamp on the skip path, or give
   the manifest entry a `when` that excludes rows with `numberedPinyin` set.

2. **`backfill-longdef-citations` requires `ANTHROPIC_API_KEY` even when it has
   nothing to translate.** Run outside oracle mode it dies with
   `❌ ANTHROPIC_API_KEY not set` *before* discovering that every embedded run is
   a det headword. It only completed here because oracle mode injects a
   placeholder key. Fix: move the key check after the work-detection pass, or
   skip it entirely when the row needs no translation.

3. **`backfill-cluster-definitions` writes clusters even when the per-cluster
   frequency-score sub-prompts fail, leaving `frequencyScore: null`.** In oracle
   mode the score prompts are captured on the same pass that commits the
   clusters, so the first apply necessarily lands with null scores and the row is
   then marked "clustered" — recovering requires `--force`. Worth ordering the
   score stage before the write, or treating a null score as a non-committing
   failure.

4. **Doc drift in `.claude/commands/mark-discoverable.md`.** §A1.5's reset
   `UPDATE` and §A4's verification `SELECT` both reference `"hskLevel"`, a column
   that no longer exists on `dictionaryentries_zh` (it is `difficulty smallint`).
   The A1.5 statement errored out on it during this run. Both occurrences need
   updating.
