## Concurrency

A parallel worker is running unsharded on the same box (its backup `det-20260822T151628Z-r453.sql.gz`
predates mine by ~1 minute). The invocation forbade `--shard`, so both workers draw the same
`ORDER BY … LIMIT 50` batch. Two de-conflictions were applied by hand:

1. **Scratch files namespaced** via `BACKFILL_ORACLE_PROMPTS` / `BACKFILL_ORACLE_ANSWERS` to
   `…-r427.jsonl`. Without this both workers append to one `oracle-prompts.jsonl` and read one
   `oracle-answers.jsonl`; the answer map is keyed by content hash so it would not have corrupted
   answers, but the prompts file would have interleaved unreadably.
2. **Batch taken from the tail** of the planner's 50-word list, leaving the head to the other
   worker. Evidence this worked: the §5 validator query surfaced 西瓜 (a head-of-list word)
   freshly clustered by the other worker during my round, and none of my 12 words collided.

**Recommendation:** unsharded parallel rounds are only safe by this kind of hand convention. If
two workers are to keep running, `SHARD=k/2` is the mechanism the skill provides; the tail-slice
trick is a stopgap, not a guarantee.

## Findings for the backlog

1. **`frequencyScore` silently truncates a cluster's glosses to four.**
   `server/scripts/backfill/chinese/lib/frequencyScore.js` → `createFrequencyScorer` builds
   `definitionText` as `definitions.slice(0, 4).join('; ')`. In sense mode this is applied to a
   *cluster's* glosses, so 说话's 5-gloss cluster was scored with "word" hidden from the scorer.
   Harmless in this instance (the hidden gloss was redundant), but a cluster whose defining gloss
   sits at index ≥ 4 gets scored on incomplete evidence, with nothing logged. The slice predates
   sense mode — it made sense when the input was a whole headword's definition list. Suggested
   fix: drop the slice in sense mode, or log when it bites.

2. **Export mode writes to the database.** The skill documents `BACKFILL_ORACLE=export` as
   "**No DB write, no network**". The no-network half holds. The no-write half does not: entries
   with a single definition take a local fast path that never calls `messages.create`, so
   `OracleExportSignal` is never thrown and `handleResponse` runs normally. My export pass wrote
   3 rows (语音合成, 语音学, 谁) and printed "Updated: 3". This is benign — the fast path involves
   no authored content — but the guarantee as written is false, and an operator reading "no DB
   write" may skip the §2 backup on an export-only pass. Either the doc or the fast path should
   change.

3. **"Found N entries" is pre-filter and misleads a hand-driven chain.** Every apply pass
   reported "Found 12 entries to cluster" even after 3, then 8, then 11 had been written. The
   not-yet-clustered gate does exclude them (they are re-processed as no-ops), but the count line
   makes it look like no progress is being made. Only the `Updated:` / `Failed/invalid:` summary
   is trustworthy for tracking convergence.

- **说话 "to gossip"** — I scored this 1 and split it into its own cluster, but I am not confident
  the bare 说话 carries the critical/gossip sense in modern usage at all (说闲话 does). If a native
  reviewer agrees it does not, the gloss should be pruned rather than clustered.
- **说话 "to tell stories"** — read as the Song-dynasty professional-storytelling sense (源 of
  话本), hence last place and score 1. If the cedict gloss actually meant the everyday "to tell
