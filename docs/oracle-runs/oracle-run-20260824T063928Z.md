## Anomaly encountered (resolved, not a defect)

`backfill-cluster-definitions.js` initially appeared to keep regenerating
Stage-1 (clusterer) prompt IDs across `apply` attempts for the same 6 words —
this looked like a bug during the run. It was not: the script is a **4-stage**
pipeline (clusterer → ranker → critic/confirm → per-cluster frequency score),
not the 3-stage pipeline assumed earlier in the session, and each `apply`
restarts from the first *unanswered* stage. What looked like "the same prompt
regenerating" was actually the pipeline advancing to a genuinely new stage each
time, once the prior stage's answers were supplied. Once all four stages had
cumulative answers in `oracle-answers.jsonl`, it completed cleanly
("Updated: 6, Errors: 0"). No fix needed — this is a note for the next
oracle session so the same false alarm doesn't recur: **when an oracle-mode
script reports a new promptId set after you believe you've answered
everything, re-read the new prompts before assuming it's a bug — it is very
likely the next stage of a multi-stage script, not a repeat.**
