## 6. Findings

### 6.1 NEW — multi-reading characters get the wrong component sense (real data defect)

`backfill-breakdown-senses` builds its candidate-sense menu from the component
character's **headword row**, which carries one reading. 乐 is now correctly stored as
`le4`, so its clusters are only "happy / joyful" and "to laugh". Four words in this
batch — 器乐, 乐器, 乐手, 乐理 — use the **yuè "music"** reading, which was not on the
menu at all. The script requires a verbatim pick from the list, so all four are stamped
**"happy / joyful"**, with a reviewNote recorded.

Downstream, `backfill-breakdown-elaboration` then had to spend its one elaboration
sentence on *patching the wrong gloss* ("Read yuè, 乐 means music, and this is the
device that makes it.") rather than on explaining an opaque compound — which is
explicitly not what that step is for.

**Fix direction:** component senses must be sourced per *reading*, not per headword row.
Any character whose readings were split across det rows (or collapsed to one by an A1.5
correction) will hit this. 乐/行/长/重/差/为 etc. are all exposed.

### 6.2 A1.5 defect corrected: 乐 imported with the rarest cedict reading

`dictionaryentries_zh` id 58475 held `lao4` / "used in place names" — the fourth of five
cedict readings and by far the least common. Reset to `le4` /
`["happy","cheerful","to laugh"]` with every derived column nulled, before any
enrichment ran. This is the pronunciation-check in `/mark-discoverable` §A1.5 doing its
job; worth noting that the import picked the wrong reading in the first place.

### 6.3 The §A1.5 SQL template in the skill is stale

does not exist** on `dictionaryentries_zh` — the column is `difficulty`. The template
errors as written. Substituted by hand this round; the skill file should be corrected.
