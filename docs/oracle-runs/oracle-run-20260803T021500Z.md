## Findings for a human

1. **`backfill-breakdown-senses.js` writes to the DB during the export phase.**
   `callTagger`'s bare `catch` at `server/scripts/backfill/chinese/backfill-breakdown-senses.js:159`
   swallows **every** exception including `OracleExportSignal`, then falls through to
   `defaultCluster(clusters)` and commits the `UPDATE` at line 284. The export run for 山水
   reported `Updated: 1`, and the subsequent apply run found `0 entries to sense-tag`
   because the row was already written. This violates the oracle contract that export
   performs no DB write, and it means the *fallback* answer ships rather than the authored
   one. Here the fallback happened to equal the authored answer exactly (山 = first cluster
   `mountain / hill`, 水 = first cluster `water; river`), so the stored data is correct —
   but that was luck, not the gate working. Fix: re-throw when `e.oracleExport` is set.
2. **Unstamped-but-populated rows are invisible to a script's own `doneGate`.**
   frequency-score needed `--stale` to run at all even though the planner listed it. The
   planner reports version-staleness; the scripts' default gates are null-only. Worth
   noting in the skill that a planner-listed step whose script reports "0 entries" should
   be retried with `--stale` before being treated as a no-op.
