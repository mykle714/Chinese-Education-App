## Why the run stopped

Preflight (§1.2) returned:

| Limit | Utilization | Resets |
|---|---|---|
| `five_hour` | **0.0 %** | `null` (no window open) |
| `seven_day` | **100.0 %** — `severity: critical`, `is_active: true` | 2026-08-24T00:59:59Z |

The five-hour session budget this skill is designed to consume is empty, but the
**weekly plan budget is fully exhausted**. `extra_usage` is enabled
(`used_credits: 13178` ≈ **$131.78**, `spend_limit_reached: false`), so requests would
still succeed — by billing paid overage credits rather than plan budget.

That inverts the premise of the skill, which exists to run the enrichment pipeline
**"without spending API credit"** by substituting a local answerer for the billed
`anthropic.messages.create` call. With the weekly pool at 100 %, every token this
session authors is a real-dollar charge. §6b already states the principle for the
parallel case — *"if [`seven_day`] is near 100 %, more workers buy nothing"* — and it
applies at least as strongly to the solo case: at 100 % the run buys enrichment with
money, not with an otherwise-idle plan allowance.

Spending money is not a decision an unattended cron round should make on its own, so
the round was not started.

  one and it does not reset until 2026-08-24T00:59:59Z.
- Not a backlog exhaustion. The planner was not consulted; the zh `--new` corpus is
