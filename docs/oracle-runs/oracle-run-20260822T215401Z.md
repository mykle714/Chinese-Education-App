## Findings / defects

1. **`oracle-plan.js` has no claim or lease.** A second, concurrent interactive session was
   already working the identical plan head (世交-family) with its own scratch files. My
   applies reported "Found 0 entries" because the other worker's writes had closed the gates
   first. No double-write was committed, and I moved to a disjoint slice. Two unsharded
   workers on one box will always collide on the plan head; either always shard, or add a
   short-lived claim table to the planner.
2. **`backfill-tones` / `backfill-numbered-pinyin` under-report without `--stale`.** They gate
   on `tone IS NULL` / `numberedPinyin IS NULL`, so a populated-but-unstamped legacy row prints
   "Found 0 … needing backfill" while `promote-discoverable.js` still blocks on it. The
   promoter's `✗ not ready` line is the only signal that anything is wrong. Consider making
   `--stale` the default for the deterministic steps.
3. **Two scripts abort on a missing `ANTHROPIC_API_KEY` even in oracle mode**
   (`backfill-longdef-citations`, `backfill-example-sentences`), which is wrong for a mode that
   never reaches the network. Worked around with `ANTHROPIC_API_KEY=oracle-dummy`.
4. **Non-exemplifiable senses are still assigned sentences.** `数量`'s "scalar quantity (maths)"
   and `量`'s "measure word (classifier)" exist in cedict but only as bound forms (标量, 量词).
   The generator is instructed to cover them, which manufactures a reviewer rejection and an
   Opus repair every time. Cluster senses that only surface as bound forms should be marked
   non-exemplifiable so the generator can skip them.
5. **Budget:** `seven_day.utilization` was already **100.0%** at preflight (resets
   2026-08-24T00:59:59Z; extra usage enabled, `used_credits` 34889.0). `five_hour` was 0.0%.
   The round was completed under the user's explicit single-round instruction; a longer
   run-to-exhaustion loop would be spending overage.
