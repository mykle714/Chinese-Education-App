## Why this scope

The two cron workers are `SHARD=0/2` / `SHARD=1/2` with `ORACLE_LANGS=zh`, and
`oracle-cron.sh` never passes `--with-icons` (grep count: 0) — `backfill-icons` is
`optional: true` in both manifests, so it is excluded from every planner round. An icons
round therefore races nothing and needs no shard identity, which is the only reason an
unsharded round was safe here. zh icons were separately in flight as a live API-key drain,
so es was the one unclaimed slice.

## Findings

### 1. es seed search terms are comma-packed synonym lists (real defect)

`buildSearchTerms` seeds from `iconSearchTerm(definitions[0])`. For zh that is one gloss;
for es the Wiktionary import routinely packs several synonyms into a single gloss, so the
seed term becomes the whole list. Two consequences:

- **HTTP 400.** `agradecido`'s seed is `"grateful, thankful, appreciative, obliged, indebted"`
  (48 chars) and icons8 rejects it outright. The word errors out of the batch entirely and
  can never receive an icon — this is not a soft failure, the row is skipped every run.
- **The search matches the LAST synonym.** `abogado` seeds `"lawyer, solicitor, counsel"` and
  returned *Counselor* (Healthcare/Health Workers — a therapist). `arma` seeds `"weapon, arm"`
  and returned *Robotic Arm*. `ascensor` seeds `"elevator, lift"` and returned
  *Not Working Elevator*. `autopista` seeds `"motorway, freeway"` and returned *Traffic Jam*.

Corpus-wide on discoverable es rows: **136 of 1257 (11%)** have a comma in `definitions[0]`;
33 exceed 40 chars and 15 exceed 60 chars — the 400 risk band.

**FIXED in v5** (commit `88d8b31`, deployed to prod the same session). `iconSearchFragments`
splits a gloss on commas — parentheses stripped first, so a comma inside a parenthetical
yields no fragment — and `MAX_SEARCH_TERM_LENGTH` (40) caps a long comma-free gloss.
`searchTopIcon` now treats HTTP 400 as "no results for this term" and advances the cascade;
401/429/5xx still throw, so an outage cannot masquerade as a corpus of empty icons.

Verified on prod against the two words that motivated it — both now resolve on the **first**
attempt, where v4 burned all four and ended NULL:

| word | v4 seed term | v4 outcome | v5 seed term | v5 outcome |
|---|---|---|---|---|
| `agradecido` | `grateful, thankful, appreciative, obliged, indebted` | HTTP 400, errored every run | `grateful` | *Thank You* (People/State of Mind), 4/5 |
| `abogado` | `lawyer, solicitor, counsel` | *Counselor* (a therapist) → NULL after 4 | `lawyer` | icon named *lawyer*, 4/5 |

Note the version bump is nearly free here: this script's doneGate is `"iconId" IS NULL` and
never reads `enrichmentLog`, so v5 does not re-run rows that already have an icon — it moves
only the planner's staleness view for the opt-in `--with-icons` path.

### 2. icons8 search is non-deterministic, which oracle mode cannot converge on

The same term returns different icons across runs — `"leisure activity"` gave *Fishing* on
one pass and *Parachute* on the next; `abogado`'s seed gave *Counselor* then *Themis*. In
normal mode this is harmless (the judge answers live). In **oracle mode** each new icon is a
new `(model, system, messages)` hash, so `apply` needs one more authored answer and the word
never converges: `afición` was abandoned after 5 passes, still stamped at version 1 and
therefore a candidate forever. Words that end sub-floor are the ones affected, because they
are the ones that keep searching. Worth recording in the skill: **`backfill-icons` cannot be
driven to convergence under oracle mode for words that do not accept early.**

### 3. `amount: 1` brand-logo failures are far worse on es than on zh

8 of 24 first-pass candidates were brand logos: *C Sharp Logo* (agudo), *Disney Now* (ahora),
*Matrix Spoon* (ahí), *Just Eat* (almorzar), Google *Hosting* (amarillo), *The Weather Channel*
(ayer), Google *Blue* (azul), Nike *Slogan* (bastar). Also *Dart* (Logos/Software Development)
for acertar. This is the same ranking weakness seen on zh (Fortnite, Samsung Flow) but at
roughly triple the rate, because es glosses are short common English words that collide with
product names. `amount: 5` + pick-best remains the standing proposal.

### 4. Colour words have no viable icon, and the floor correctly says so

`amarillo` and `azul` each burned all four attempts. Every candidate depicted an object that
has its own Spanish headword — banana/plátano, sun/sol, taxi, water drop/agua, paint bucket —
so the icon would teach the wrong word. Both correctly ended NULL. This is a genuine category
limit, not a tuning problem; colour words should probably be excluded from the step.

### 5. The score floor behaved correctly throughout

Every sub-floor word ended NULL with no `icons8` row created. `abogado` is the clearest case:
its best candidate across four attempts was *Judge* (People/Professions), which would have
taught **juez** — a different, high-frequency Spanish word. Under v3 that would have shipped.
