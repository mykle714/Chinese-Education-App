## Process note: `backfill-tones` / `backfill-numbered-pinyin` and `--stale`

Both scripts' own doneGate (`tone IS NULL` / `numberedPinyin IS NULL`) reported "0
entries needing backfill" for this batch, but `promote-discoverable.js`'s dry-run
initially reported all 25 words `✗ not ready: backfill-tones,
backfill-numbered-pinyin`. Root cause: the columns already held data (populated at
import time), so the doneGate looked satisfied, but `enrichmentLog` had never been
stamped for either script — and the promotion bar checks the **stamp**, not the
column. Resolved by re-running both with `--stale` (reprocesses
populated-but-unstamped rows purely to write the version stamp, per each script's
own doc comment): `backfill-tones --stale` stamped 19 rows, `backfill-numbered-pinyin
--stale` stamped 25 rows. After that, the promoter's dry-run showed all 25 ready.

**Lesson for future rounds:** a script reporting "0 pending" is not sufficient
evidence a batch is promotion-ready — always check `promote-discoverable.js`'s own
dry-run output before trusting completeness, since "column populated" and "stamped"
are not the same thing.
