## Findings for later (not fixed this run)

- `backfill-cluster-definitions.js:467` swallows a per-cluster frequency failure into a
  review note and writes the clusters anyway with null scores. Under oracle mode this is
  guaranteed on the first apply pass (the score prompts cannot exist yet), so every
  clustering round costs an extra `--force` re-run. A cleaner fix would be to let the
  `OracleExportSignal` propagate out of the frequency sub-call rather than be caught, so
  the row unwinds instead of half-writing.
- `--dry-run` on the clusterer is unusable under oracle mode (it hits the real API path
  and dies on the missing key), which conflicts with the skill's "always dry-run the
  clusterer first" instruction for es.
