## Findings (recorded, not acted on)

1. ⭐⭐ **`backup-det.sh`'s retain-1 pruning is unsafe under parallel workers.** It prunes
   *globally*, not per worker. My round's pre-write backup
   (`det-20260822T121722Z-r365.sql.gz`) was deleted by the parallel worker's next
   round (`…122231Z-r367`) **while my round was still writing**, so the rollback point
   §2 exists to guarantee was gone before the round finished. §2 says "record the path —
   it goes in the report", and the path in this report points at a file that no longer
   exists. Suggested fix: retain-N where N ≥ number of concurrent workers, or namespace
   the prune by the backup's label/shard the way `oracle-cron.sh` namespaces the scratch
   files.

2. ⭐⭐ **The §5 validator-guard query cannot distinguish "a protected column was written"
   from "the row's stamp moved".** It joins `validations` to any row whose script stamp is
   newer than the run start, regardless of whether that script writes the validated field.
   For `backfill-cluster-definitions` — which writes only `definitionClusters` but stamps
   every row it touches — any batch containing a row with *any* validation produces a false
   hit. Since the skill makes a hit a hard stop condition, this will halt unattended runs
   on rows that were handled perfectly correctly. Suggested fix: restrict the query's
   `val.field` to the fields the script in question actually writes (for the clusterer,
   `senseFrequencyScore`), i.e. mirror `validatedClause`'s own field list.

3. ⭐ **`loadOracleAnswers()` caches a failed load as an empty map, converting a hard error
   into silent re-export.** In `server/scripts/backfill/run-log.js`, `oracleAnswers` is
   assigned `new Map()` *before* the `readFileSync`, so when the read throws, the first row
   reports `oracle-apply: answers file not found` but every subsequent row finds an empty
   (yet truthy) cache, treats each prompt as "not yet authored", and re-captures it as if in
   export mode. The observed output was one file-not-found line followed by ten
   `oracle-export: captured prompt` lines — which reads like normal chained-call convergence
   rather than a fatal misconfiguration. Suggested fix: only assign `oracleAnswers` after a
   successful read, so the throw repeats on every row.

4. **`BACKFILL_ORACLE_ANSWERS` / `BACKFILL_ORACLE_PROMPTS` must be absolute paths.**
   `run-prod.sh` changes directory into `server/`, so a repo-root-relative path silently
   resolves to the wrong location — and finding 3 turns that into a quiet no-op rather than
   an error. Worth a note in the skill, or a `path.resolve` against the repo root in
   `run-log.js`.

5. **The oracle's authored `sense` labels are not always what gets stored.** I authored
   `"tabletop / countertop"` and `"stake on the table"` for 台面; the stored labels are
   `"tabletop surface"` and `"gambling stake"`. One authored frequency score also differs
   from the stored value (台面 "public view": authored 3, stored 2). A downstream
   normalization/consolidation pass is evidently rewriting Stage-A output. This is not
   wrong — but it means **the report's "content authored" and the DB's content are not the
   same artifact**, and a reviewer comparing them will see drift that has nothing to do with
   the answerer. Worth documenting in `docs/DEFINITION_CLUSTERS.md`.

6. **Content observations on this batch** (continuing the running corpus-quality log in
   `server/logs/oracle-run-notes.md`):
   - **机头** is a *pure duplicate pair*: "nose of a plane" and "the front (nose) of a plane
     etc" are the same gloss written twice. A new shape — not a breadth drift, not a wrong
     gloss, just redundancy that will render as two bullets on a card.
   - **机车's "crap!"** carries no `(Tw)`/`(slang)` marker while its sibling `(Tw) damn!`
     does — another instance of an owned annotation convention going unapplied within a
     single row.
   - **机会主义 → "pragmatism"** is a *polarity* error, not a breadth error: 机会主义 is
     pejorative, "pragmatism" is neutral-to-positive. Distinct from the wrong-gloss and
     breadth-drift classes already logged, and invisible to a synonym-overlap check.
   - **机体's two glosses have no shared origin at all** ("organism" from 有机, "airframe"
     from 飞机). The commonest justification for a hard cluster split so far.
