## 6. Findings

### 6.1 Systemic — breakdown candidate-label coverage

By far the largest recurring source of `BREAKDOWN SENSE REVIEW` flags: the
candidate sense-label set offered per character comes from the character's own
dictionary senses, and has **no label at all** for a long tail of uses. Observed
repeatedly across rounds 11–95:

- figurative / extended senses (the literal label is forced onto a metaphor)
- abbreviation components (国 for 中国, 语 for 语言)
- causatives, and verb-complement uses generally
- proper nouns, place names, and surname characters
- **transliteration syllables** (阿, 巴, 拉, 斯, 德 in 阿拉法特, 巴巴多斯, 路德) —
  the single largest cluster; these characters carry no sense at all in the word
- radicals / shape-of-the-character senses (一字 "the shape of 一", 之字路 "zigzag")
- reduplication linkers (时A时B, 神神道道)
- classical interrogatives (安 "how could…?"), and 得 in fixed classical frames
- agentive 主, degree-complement 得很, **potential-complement 得 (V-得-C)** —
  `行得通`, `数得上`, `长得` all mis-map 得 onto "to allow"
- stance 马 (一字马)

**Fix worth considering:** add a small fixed vocabulary of structural labels —
`transliteration syllable`, `abbreviation of X`, `potential-complement marker`,
`proper-noun component`, `shape of the character`, `reduplication linker` — that
`backfill-breakdown-senses` may assign in addition to the dictionary senses. That
one change would silence a clear majority of the 464 flags and materially improve
the bt for loanwords and names.

### 6.2 Data-quality / pipeline bugs found

| # | Finding | Impact |
|---|---|---|
| 1 | **`process-definitions-array` short-gloss step prepends the gloss as a new *first* definition**, producing near-duplicate leading pairs. Hit on 一字马, 三音, 儿化音, 阿得拉, 合字, 合体字, 名字, 国音 and many earlier. | Cosmetic-to-real: the dd and the det list both show a near-duplicate pair. Worth making the step *replace* the lead definition when it is a paraphrase of it, or dedupe after. |
| 2 | **Short-gloss prompts only surface after earlier pda waves apply**, so an authored gloss map has to be extended mid-loop and the loop re-run (round 95: 国字, then 合音). | Process friction only — costs 1–2 extra export/apply cycles per round. |
| 3 | **`backfill-classifier.js` prints a `Failed: N` line even when every row was written** (round 91). | Misleading operator output; the run looks partially failed when it is clean. One-line fix in its summary print. |
| 4 | **`cluster-definitions` ordering-echo and frequency-score prompts are distinguishable only by their system prompt** — the user message shape is identical. | Makes an automated answerer fragile; a `kind` field in the exported prompt record would fix it cheaply. |
| 5 | **`backfill-cluster-definitions.js` swallowed `OracleExportSignal` in its frequency-score catch block**, so those prompts never reached `oracle-prompts.jsonl`. **Fixed in-run** (rethrow `e?.oracleExport`) — see §7. | Was a hard blocker for oracle mode on that stage. |
| 6 | The cluster stage needs **4–6 export/apply cycles** to converge because ordering and frequency waves interleave; pda needs 3–5; long-definitions 2. | Not a bug, but it dominates round wall-clock. A stage that emitted all its waves' prompts up front would roughly halve a round. |

### 6.3 gsa (greedy segmentation) artifacts

Example-sentence segment metadata repeatedly exposed mis-segmentation. Collected
this run:

| Sentence fragment | Segmented as | Should be |
|---|---|---|
| 那天山上 | 那 + 天山 + 上 | 那天 + 山上 |
| 要点药水 | 要点 + 药水 | 要 + 点 + 药水 |
| 路得记 | 路得 + 记 | 路得记 (book title) |
| 排开站好 | 排 + 开站 + 好 | 排开 + 站好 |
| 从小就学 | 从小 + 就学 | 从小 + 就 + 学 |
| 标的 | 标 + 的 as one segment | context-dependent |

The pattern is consistent: the gsa prefers a longer dictionary match spanning a
word boundary. Each of these was answered honestly (labelling the segment the gsa
actually produced), so the data is self-consistent, but the segmentation itself is
wrong in the est for those sentences.

### 6.4 Process notes for the next run

- `--stale` tones and numbered-pinyin generate **no prompts** — they are pure
  recomputation. Run them, but do not budget answering time.
- `longdef-citations` must be run under **export** and typically reports
  "Nothing to translate" for an all-zh batch.
- Every apply re-runs the chain from wave 1, so `oracle-answers.jsonl` must hold
  **all** waves at once — append, never overwrite, after the first wave.
  `FAILED: oracle-export: captured prompt <id>` is normal chained flow, not an error.
- Guard authored long-definitions locally before apply
  (`25 <= len <= 200`, `isascii()`, 1–3 sentences); one 215-char definition (一字)
  was caught this way instead of by a failed apply round trip.

## 8. Honest limitations of oracle mode

Stated for the record, as the skill requires — this is disclosure, not a defect
report:

1. **The answerer and the reviewer are the same session.** Every judgement call
   above (sense clustering, POS, HSK level, example sentences) was made and then
   reviewed by me. The validators are independent and unmodified, so contract
   violations are caught mechanically; *semantic* errors are not.
2. **That is exactly what the 868 review flags and the validator flow are for.**
   Rows are marked `oracle: true` in `enrichmentLog`, so every row this run touched
   is identifiable and re-checkable.
3. **Difficulty skew.** 80 % of this run's words landed at HSK 5–6. Learners at
   lower levels gain little from this batch; a future run may want the planner to
   support a level-targeted `--new` scope.
