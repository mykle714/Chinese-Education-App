## Findings

1. **Planner `--new` curation has no propriety filter (recurring, rounds 519–526).**
   `oracle-plan.js`'s character-commonness ranking happily leads with explicit and
   slur headwords, so most of each 25-candidate batch is unusable and the round's
   effective yield is ~half. A headword-quality predicate alongside the existing
   `%`/`110`/`surname X` stub filter would fix this.
2. **Unstamped-value gating (recurring).** `backfill-tones` and
   `backfill-numbered-pinyin` gate `doneGate` on the column being NULL rather than on
   the enrichment stamp, so already-populated-but-unstamped rows report "0 needing
   backfill" while `promote-discoverable.js` still blocks on the missing stamp.
   `--stale` is the standing workaround.
3. **`process-definitions-array` re-processing loop (recurring).** The junior→critic
   chain plus re-ranking of the mutated `definitions` array produces a fresh `promptId`
   on each pass; 6 export→apply cycles were needed to converge.
4. **Example-sentence chain is 5 cycles deep** — generation, native review, then
   segment labelling at **one prompt per sentence per cycle** (3 cycles for 3 sentences).
   The labelling stage does not fan out across a word's sentences in one export, which
   is what makes this step dominate a round's wall time.
5. **GSA mis-segmentation (recurring).** 你不觉得 was segmented 不觉 + 得 instead of
   不 + 觉得. The labelling prompt forbids re-splitting, so the stored segment metadata
   for that sentence is structurally wrong even though every label is the best available
   given the segmentation.
6. **Self-flagged for human review.** `⚠ BREAKDOWN SENSE REVIEW` on 打鱼 (打 as light
   verb vs "to hit, strike") and 气量 (气 as "vital energy (qi)"); 3 `⚠ CLUSTER REVIEW`
   flags on 气量, 量化, 鱼子.
7. **Judgement call worth a second opinion:** 木鱼's classifier was authored as `["只"]`.
   The most natural counter is 个, which the prompt explicitly bars as a catch-all.

## Disclosure

The oracle answers and reviews its own prompts, so the native-reviewer and critic stages
are not independent of the generation stage. The pipeline's mechanical validators
(schema, length caps, verbatim-label matching, `promote-discoverable.js`'s completeness
predicate) *are* independent, and they caught two real authoring errors this round: a
206-character long definition against a 200-char cap (木鱼) and a wrong-sense long
definition (美人鱼, dugong instead of mermaid).
