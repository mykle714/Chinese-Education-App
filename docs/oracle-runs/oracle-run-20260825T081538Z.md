## Script-behavior findings this round

1. **Multi-stage oracle pipelines expose exactly one new stage per `apply` call.**
   `backfill-example-sentences` in particular required repeated
   append-to-`oracle-answers.jsonl`-and-reapply cycles per word until every stage
   (draft → repair → segment-tag → final-tag, as applicable) cleared. Confirmed
   again this round for 传/传代.
2. **Deterministic (non-AI) backfill scripts can read "0 pending" against their own
   `doneGate` while the planner still lists them pending**, when the target column
   is already correctly populated but unstamped in the run-log (e.g. from an
   earlier partial run). `backfill-tones` and `backfill-numbered-pinyin` (neither
   calls `anthropic.messages.create` — they compute purely from existing columns)
   both hit this. Fix is the scripts' own documented `--stale` flag, which extends
   the gate to `column IS NULL OR staleClause()` and stamps already-correct rows
   without recomputing them. Seen in 3 consecutive rounds now (04:17:23Z, 06:17:24Z,
   this round) — worth considering whether these two scripts' gates should default
   to stale-inclusive, since the failure mode recurs every time a batch survives a
   mid-round compaction or partial run.
3. **`backfill-cluster-definitions.js` has no `doneGate`** and unconditionally
   re-clusters on every invocation (inherited finding from an earlier round, not
   re-verified this round).
