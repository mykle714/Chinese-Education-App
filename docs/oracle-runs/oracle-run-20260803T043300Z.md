### breakdown-senses — structurally skipped (soft miss)

Reported `Processed: 1, Updated: 0, Skipped: 1` on both a plain run **and** under
`--force`, emitting **no prompt**. Root cause, confirmed against the DB:

`tagEntryBreakdown` (`server/scripts/backfill/chinese/backfill-breakdown-senses.js:170-201`)
reads `definitionClusters` off each component character's **own det row**. Both 风 and
景 have `definitionClusters = NULL`, so every char falls into the
`if (clusters.length === 0) continue;` branch, `decided.size === 0`, the function
returns `null`, and the row is counted as skipped before any tagger call.

This is the documented soft miss, not a failure — the breakdown is carried through
unchanged (correct glosses, no `sense` tags) and will heal automatically once 风 and 景
are themselves run through `backfill-cluster-definitions`. `oracle-plan.js --words=风景`
therefore still lists `backfill-breakdown-senses` as pending and will keep doing so until
that happens; the step is unreachable, not undone.

Incidental benefit: because the tagger was never called, the export-phase-write bug
recorded as finding #1 of the 山水 run (it lives in `callTagger`'s bare catch) never

## Findings for a human

1. **`--stale` is needed more often than the planner implies** — second occurrence in two
   runs (山水 frequency-score, 风景 numbered-pinyin). A planner-listed step whose script
   reports "0 entries" is almost always an unstamped-but-populated row, not a no-op. Worth
   codifying in the skill: retry with `--stale` before treating a step as done. Better fix:
   make `oracle-plan.js` print `--stale` in the suggested command when the row it selected
   is version-stale rather than null.
2. **`breakdown-senses` will re-list forever on words whose components are unclustered.**
   The planner has no way to tell "pending" from "structurally unreachable", so a scoped
   plan can never reach 0 prompts for such a word. Consider having the manifest's `when`
   predicate for this step also require ≥1 component char with non-null
   `definitionClusters`, so the step reports as inapplicable rather than pending.
3. The 山水 finding — `backfill-breakdown-senses.js:159`'s bare catch swallowing
   `OracleExportSignal` and committing the fallback during export — is **still open**. It
   did not trigger this run only because the tagger was never reached.
