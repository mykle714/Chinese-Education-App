## Findings

1. **Deterministic steps need `--stale` on populated-but-unstamped rows.** `backfill-tones`
   and `backfill-numbered-pinyin` gate on `column IS NULL` only, so they reported 0 rows
   while `promote-discoverable.js` still reported the step missing. `--stale` resolved it
   (12 and 19 rows). Worth making the planner print `--stale` in the command it suggests.

2. **`backfill-longdef-citations` checks `ANTHROPIC_API_KEY` before deciding there is
   nothing to do.** Run outside oracle mode it aborts with `❌ ANTHROPIC_API_KEY not set`
   even though its verdict for all 25 rows was "nothing to translate" (no embedded Chinese).
   The key check should move after the work-selection step. In this run the export pass had
   already written the stamp, so no re-run was needed.

3. **gsa mis-segmentation reaching example sentences.** Two sentences were handed to the
   segment-labelling stage with wrong segment boundaries, and the stage is contractually
   forbidden from re-splitting:
   - `请加入同量的糖和面粉。` → `糖 / 和面 / 粉` (should be `糖 / 和 / 面粉`)
   - `你知道这台风机一天的发电量吗？` → `这 / 台风 / 机` (should be `这 / 台 / 风机`)
   Both got a least-bad label (`和面` as a conjunction; `台风` as noun/"typhoon"), so the
   stored per-segment metadata for those two sentences is wrong. The greedy longest-match
   rule prefers the longer 和面/台风 over the correct split; a frequency tiebreak or a
   "don't cross a 的-phrase head" guard would fix both cases.

4. **Content-declined frontier words are re-offered forever.** The `--new` frequency frontier
   currently opens with a block of 19 pornographic / sexual-slang / ethnic-slur headwords
   (法克, 马上风, 工口, 马眼, 阿三, 小日本, 口交, 性交, 手交, 台巴子, 黄书, 情色, 色情,
   老黑, 色情业, 日人民报, 基情, 尼格罗, 木子美 — the last is a person's name, not
   vocabulary). Per §6 they were dropped and the round was filled from the next clean words
   in the same planner order (`--limit=70`). **There is no "declined" marker**, so the planner
   will re-offer these 19 on every future run and the frontier is permanently blocked behind
   them. The zh `--new` junk filter screens stubs (`%`, `110`, `A片`, `surname X`) but not
   slurs or explicit content. Suggest either a `declined` boolean on the det row or a
   checked-in denylist consulted by `CHAR_FREQ_CTE`.

5. **Budget: `five_hour.utilization` reads 0.0% and never moved all round.** That is the
   flat-usage signal §6 asks about, but the cause is visible and benign: `seven_day` is at
   **100.0%** (resets 2026-08-24T00:59:59Z) and the session is running on extra usage —
   `extra_usage.is_enabled = true`, credits used rose from **38627 → 39752** over this round
   (~1125 credits for 25 words). So consumption is being metered, just on the extra-usage
   counter rather than the five-hour one. Not treated as a stop condition.
