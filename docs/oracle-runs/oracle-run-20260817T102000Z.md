Two hazards follow, and they are the reason to stop rather than keep looping:

1. **Shared oracle scratch files.** Both sessions read and write
   `server/logs/oracle-prompts.jsonl` and `server/logs/oracle-answers.jsonl`.
   This session ran `rm -f server/logs/oracle-prompts.jsonl` before each export
   (the procedure the skill prescribes), which **destroys the other session's
   captured prompts** mid-cycle. Its `FAILED: oracle-export: captured prompt …`
   loops after 10:14Z are consistent with that.
2. **Racing plans.** The planner is read-only, so both sessions can be handed
   overlapping `--words=` lists and each will author the same prompts. Nothing
   is corrupted in the DB (every write re-derives its own gate), but the work is
   duplicated and the answers files diverge.

**Recommendation:** run one oracle session per machine, or give each session its
own `server/logs` (the prompts/answers paths are hard-coded, so today that means
a separate working copy). This is worth a line in the skill.

## 3. The batch: one defect, two words

行头 and 重 were **already discoverable** and both carried the same defect: one
det row conflating two cedict readings, with the **less popular reading stored as
the row's `pronunciation`**, so every downstream enrichment column had been
generated from a false premise.

| word | id | stored before | cedict readings |
|---|---|---|---|
| 行头 | 97228 | `háng tóu` / `hang2 tou2` / tone 22, difficulty 6 | `[hang2 tou2]` team leader, shopkeeper (archaic) · `[xing2 tou5]` clothing, outfit, actor's costume |
| 重 | 109657 | `chóng` / `chong2` / tone 2, difficulty 3 | `[chong2]` repeat, again, re-, classifier: layer · `[zhong4]` heavy, serious, to attach importance to |

Evidence the old data was downstream of the wrong reading: 行头's
`definitionClusters` tagged **both** clusters `"reading": "hang2 tou2"` —
including the outfit/costume cluster, which is only ever xíng — and its
`breakdown` glossed 行 as "trade; profession" (the háng sense). After the repair
the deterministic breakdown regenerated 行 as the xíng lead gloss.

几个 (37891) already had correct pinyin and needed no repair; it was folded into
the batch because it was unenriched and not discoverable.

### Repair procedure (`/mark-discoverable` §A1.5)

One transaction set the correct `pronunciation`, set `discoverable = FALSE`, and
nulled every derived column (`numberedPinyin`, `tone`, `partsOfSpeech`,
`difficulty`, `frequencyScore`, `longDefinition`, `longDefinitionCitations`,
`definitionClusters`, `exampleSentences`, `classifier`, `wordForms`, `synonyms`,
`breakdown`, `breakdownElaboration`, both pronunciation-override columns) and
reset `enrichmentLog` — preserving only the opt-in `backfill-icons` stamp.
`UPDATE 2`. The rows were then re-enriched through the full manifest and
re-promoted by `promote-discoverable.js`.

Dropping `discoverable` for the duration is deliberate: a half-enriched row must
never be live, and the promoter restores the flag only once it re-derives the
whole bar.

**`definitions` was deliberately left merged.** One row per headword with a
per-cluster `reading` *is* the heteronym model (a differing reading is a hard
cluster boundary), so merged glosses are correct by design. The bug was the
row-level primary reading plus wrongly-tagged cluster readings, not the merge.

## 5. Self-flagged review notes (verbatim)

These were emitted deliberately by the oracle and surface here because they feed
the downstream example sentences.

**⚠ CLUSTER REVIEW 几个** — "Split the declarative 'a few / several' from the
interrogative 'how many'. They share one origin (indefinite small quantity 几)
and could reasonably be ONE cluster; split because a learner meets them as two
distinct uses (你有几个? vs 我买了几个)."

**⚠ CLUSTER REVIEW 行头** — "行头 is a heteronym and cedict lists the two readings
separately: [xing2 tou5] clothing/outfit/actor's costume vs [hang2 tou2] the
archaic guild-head senses. Clusters follow that split; the entry's primary
reading was corrected from hang2 tou2 to xing2 tou this run." · "Kept 'actor's
costume' with the everyday 'outfit / clothing' rather than splitting it out:
opera costume is the origin of the colloquial sense and is a DOMAIN difference,
not a register gap. Flagging in case you would rather see the theatrical sense on
its own."

**⚠ CLUSTER REVIEW 重** — "重 is a heteronym: 'heavy / serious / to attach
importance to' are zhong4; 'again / to repeat / re- / repetition / classifier:
layer' are chong2 (cedict lists them as two entries). The entry's primary reading
was corrected from chong2 to zhong4 this run, so the chong2 clusters are
deliberately non-primary." · "Split 'heavy' from 'serious' even though severity
is a straightforward metaphorical extension of physical weight — erring finer per
rule 3. Merge them if you'd rather one weight cluster." · "'a layer / a fold'
(classifier) is split from 'again / to repeat' though both are chong2 and
arguably one 'repeated layer' origin; the classifier use is also literary (万重山)
while 重来/重做 are everyday, which is a register gap too."

**⚠ BREAKDOWN SENSE REVIEW 行头** — "行: the reading is xíng, not háng, so the
'trade; profession' sense is ruled out by the pronunciation; picked the travel
sense on the 行装/行囊 analogy (gear one takes along). Worth a human check — the
theatrical-costume origin is sometimes traced to 行当 instead."

**This is the note to look at first.** 行头's breakdown now reads 行 = "to go" +
头 = "(noun suffix)", with the elaboration "The gear you put on before heading out
— on the street or onto a stage." That elaboration is a mnemonic bridge, written
that way on purpose rather than as an etymological claim, because the origin is
disputed.

## 7. Findings for follow-up (none blocked the run)

1. **几 (id 12875) has the same defect, unfixed.** `pronunciation` is `jī` while
   its definitions are the jǐ senses ("a few", "almost", "how many", "how much",
   "several", "small table"). It is **not** discoverable, so nothing ships wrong
   today, but it will if enriched as-is. It needs the §A1.5 treatment before it
   is ever picked up by a `--new` batch. Worth a sweep for the general case: any
   row whose stored reading is not the most popular cedict reading for that
   headword.
2. **The `--new` curation filter lets through content that should not be a
   learner card.** The head of this round's plan was 法克 ("fuck", loanword),
   马上风, 工口, 马眼 and 阿三 (an ethnic slur) — all five were dropped from the
   batch per §6 and none were authored. Immediately behind them the ranking is
   dominated by toponym stubs ("Xishan District", "Changbai Mountains",
   "Wen County"). The commonness score is doing its job on obscure characters but
   nothing screens vulgarity/slurs or place-name stubs. Suggest extending
   `oracle-plan.js`'s `--new` scope the way it already drops `surname %`.
3. **`chinese/backfill-dictionary-breakdown` is deterministic** (it exported no
   prompt) but the manifest entry in
   `server/scripts/backfill/shared/lib/requiredScripts.js` does not mark it
   `deterministic: true`, unlike its peers. Cosmetic, but it makes the planner's
   prompt count read high.
4. **`/mark-discoverable` §A1.5's SQL template still names `"hskLevel"`**, a
   column that no longer exists — it is `difficulty` now. Anyone pasting that
   template gets an error. (This run used a corrected copy.)
5. **The planner truncates its word lists at 8** (`words.slice(0, 8)` plus
   `…+N`), including in the `promote-discoverable.js` line it prints, so a batch
   larger than 8 cannot be copy-pasted or even fully read from the plan output.
   Suggest printing the full list, or adding a `--full` flag.
